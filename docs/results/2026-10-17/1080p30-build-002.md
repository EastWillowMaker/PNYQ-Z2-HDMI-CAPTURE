# Second 1080p30 loop build: asynchronous reset metadata

Revision `0d35411` was exported to `artifacts/1080p30-source-002` and built in
the fresh `artifacts/1080p30-loop-002` directory. The complete console log is
`artifacts/1080p30-loop-002.console.log`.

Fresh HLS synthesis/export and drain simulations passed. The clock-frequency
and polarity errors from build 001 were resolved. Block-design validation
still produced one critical warning: the common serializer reset was described
as synchronous to the pixel clock while the serializer also consumes the 5×
serial clock. The generated reset is asynchronous at these module boundaries;
the pattern and pinned serializer use local reset bridges.

The correction uses the supported `ASSOCIATED_ASYNC_RESET` interface property
for both generated clocks and the pattern input. No check is suppressed and no
reset logic is removed. AMD documents the property in
[UG994 control-signal inference](https://docs.amd.com/r/2022.1-English/ug994-vivado-ip-subsystems/Inferring-Control-Signals-in-a-RTL-Module).
The full-frame/reset Icarus test passes after the metadata correction. This
failed build produced no bitstream and was not loaded on the board. A fresh
build is required to verify the remaining integration and physical timing.
