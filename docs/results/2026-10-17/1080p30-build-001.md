# First 1080p30 loop build: block-design validation failed

Revision `df5410d`, exported to `artifacts/1080p30-source-001`, was built with
pinned PYNQ v3.0.1 and Vivado/Vitis 2025.2. Output is retained at
`artifacts/1080p30-loop-001`; the complete console log is
`artifacts/1080p30-loop-001.console.log`.

Both HLS IPs synthesized/exported, and the generated HLS drain simulations
passed. Vivado then rejected the block design before synthesis:

- The output clock module lacked frequency metadata for its pixel/serial
  outputs. Its reset output was inferred as active-low despite active-high
  logic, conflicting with the serializer.
- The raw MMCM reset was inferred as a peripheral reset in its generated pixel
  clock domain, producing an asynchronous-reset critical warning.
- The copied source-health module still declared 25.2 MHz instead of the
  selected receiver's 74.25 MHz pixel clock.

No bitstream was produced or loaded. The correction declares the output clock
frequencies and reset polarities explicitly. Only the raw MMCM control is
excluded from reset-interface inference; downstream reset bridges remain.
Build preparation adapts the copied source-health clock metadata for the
selected profile, preserving the VGA source bytes exactly. Forty focused
build/HWH tests pass, and the two-frame output/reset simulation passes after
the attributes changed. A fresh isolated build is required; the failed output
and its source snapshot remain unchanged.
